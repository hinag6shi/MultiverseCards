# Отчёт о разработке Multiverse Cards

## Кратко о результате

Реализованы задачи 1 и 2 из плана: каркас Telegram-бота, профиль игрока, каталог карточек, коллекция и стартовый набор. Команды и доменная логика покрыты модульными тестами. База данных подключена и автоматически создаёт схему при запуске. Проверки с реальным PostgreSQL и ручная приёмка сценариев в Telegram остаются отдельными шагами.

## Задача 1 — каркас чат-бота

### Что сделано

- Настроен Telegram Long Polling и обработка текстовых команд и callback-кнопок.
- Созданы реестр команд, диспетчер и общий формат ответа: текст, фото, клавиатура.
- Реализованы `/help`, `/help <команда>`, `/about` и `/author`.
- Справка `/help` строится из зарегистрированных команд, поэтому новые команды появляются в списке автоматически.
- Добавлены модульные тесты для реестра и диспетчера команд, ответов, кнопок и клавиатур.

### Как устроена обработка

Апдейты одного Telegram-пользователя выполняются по очереди, а разные пользователи могут обрабатываться параллельно. Это сохраняет порядок действий игрока и уменьшает риск гонок при последующих изменениях его данных.

## Задача 2 — игрок, каталог и коллекция

### Что сделано

- Добавлены модели игрока, ID игрока, шаблона карточки, редкости, характеристик и коллекции.
- Создан общий каталог карточек. У одного игрока может быть не больше одной копии карточки с данным ID.
- Карточки вселенной Sanrio описаны в `src/main/resources/cards/Sanrio.json`; PNG-файлы находятся в `cards/images`.
- `CardJsonLoader` читает все JSON-файлы из каталога ресурсов, проверяет обязательные поля, уникальность ID и наличие изображения.
- Каталог синхронизируется с PostgreSQL при старте приложения.
- Добавлены миграции Flyway для игроков, шаблонов карточек и коллекций. База запускается через Docker Compose; настройки берутся из `.env`.
- `/start` начинает регистрацию с вводом имени и 30-секундным тайм-аутом. Имя и Telegram ID сохраняются в профиле.
- Стартовые карточки выдаются однократно. Признак выдачи хранится в базе; запись признака и карточек выполняется одной транзакцией.
- `/name <имя>` переименовывает игрока. `/about`, `/author` и `/help` обращаются к зарегистрированному игроку по имени.
- `/cards` показывает коллекцию, `/cards <id>` показывает выбранную карточку и отправляет её изображение.
- Добавлены unit-тесты доменной коллекции, каталога, сервиса игрока и загрузчика JSON.

### Почему выбрана такая структура

JSON является источником каталога: характеристики и стартовый набор можно менять без изменения кода. В коллекции игрока хранятся ссылки на общий шаблон, а не копии описаний карточек. Составной ключ `(player_id, template_id)` в БД закрепляет правило «не более одной копии» на уровне хранения.

### Текущий баланс характеристик

Редкость задаёт силу заранее подготовленных значений в JSON. COMMON-показатели служат базой: следующая редкость получает вдвое большие характеристики, вплоть до DIVINE ×64. Для персонажей без COMMON-карты используется среднее COMMON-значение вселенной. Код игры повторно коэффициенты не применяет. Усиления, осколки и бонусы за сет пока не реализованы как игровые операции.

## Проверки и ограничения результата

- Запускались тесты `CardJsonLoader`: 5 тестов прошли без ошибок.
- Модульные тесты не требуют подключения к PostgreSQL.
- Интеграционные проверки миграций и операций репозитория с настоящей базой данных не проводились.
- Ручная проверка полного сценария в Telegram (регистрация, тайм-аут, повторный `/start`, переименование и просмотр карточек) не отмечена как выполненная.
- Проверка баланса стартового набора и игровых характеристик остаётся частью приёмки.

## Принятые технические решения

- Настройки токена Telegram и PostgreSQL читаются из переменных окружения или `.env`; секреты не добавляются в Git.
- PostgreSQL запускается локально через Docker Compose с постоянным томом и healthcheck.
- Схема БД меняется миграциями Flyway. После применения миграции существующий файл не редактируют — добавляют следующий.
- JSON и изображения карточек хранятся в `src/main/resources/cards`; ID карточки соответствует имени PNG-файла.
- Проверка БД отложена; сначала проект покрывается unit-тестами без внешней инфраструктуры.
