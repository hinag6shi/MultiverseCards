# Multiverse Cards

Коллекционная игра в Telegram. Игрок регистрируется, получает стартовые карточки и просматривает свою коллекцию. Карточки хранятся в общем каталоге, а профиль и коллекция игрока — в PostgreSQL.

## Что работает сейчас

- Регистрация через `/start`: бот просит имя и ждёт ответ до 30 секунд.
- Стартовый набор выдаётся один раз и сохраняется в базе данных.
- `/name <имя>` меняет имя, которым бот обращается к игроку.
- `/cards` показывает коллекцию, `/cards <id>` открывает карточку с изображением и характеристиками.
- `/help` показывает команды, `/help <команда>` — справку по выбранной команде.
- `/about` и `/author` показывают информацию о проекте и его авторах.

Усиления, PvE, PvP, гача и магазин пока являются планами. В модели данных предусмотрены счётчики усилений и осколки, но игровой процесс их расходования ещё не реализован.

## Технологии

- Java 25 и Maven
- Telegram Long Polling
- PostgreSQL 17 в Docker Compose
- Flyway для миграций базы данных
- JSON-файлы как источник каталога карточек

## Запуск

1. Установить Java 25, Maven, Docker Engine и Docker Compose.
2. Создать файл `.env` из шаблона: `cp .env.example .env`.
3. Заполнить `BOT_TOKEN` и `DB_PASSWORD` в `.env`. Файл `.env` исключён из Git.
4. Запустить базу: `docker compose up -d`.
5. Запустить приложение: `mvn exec:java`.

При старте приложение применяет миграции Flyway, загружает JSON-каталог и проверяет, что для каждой карточки есть изображение. Чтобы остановить базу, используйте `docker compose down`. Команда `docker compose down -v` также удаляет сохранённые данные.

## Каталог карточек

Каждый файл в `src/main/resources/cards/` описывает одну вселенную. Изображения лежат в `src/main/resources/cards/images/`; имя файла должно совпадать с ID карточки.

```json
{
  "universe": "Sanrio",
  "cards": [
    {
      "id": "sanrio_badtz_common",
      "name": "Badtz",
      "rarity": "COMMON",
      "hp": 100,
      "st": 16,
      "df": 11,
      "starter": true
    }
  ]
}
```

ID уникален среди всех JSON-файлов. Допустимые редкости: `COMMON`, `UNCOMMON`, `RARE`, `EPIC`, `MYTHIC`, `LEGENDARY`, `DIVINE`. Поля характеристик — целые неотрицательные числа, `starter` — признак включения в стартовый набор.

JSON содержит готовые значения HP, ST и DF. Коэффициенты редкости применяются при подготовке каталога и не рассчитываются кодом игры. Текущая шкала удваивает характеристики на каждой следующей ступени: COMMON ×1, UNCOMMON ×2, RARE ×4, EPIC ×8, MYTHIC ×16, LEGENDARY ×32, DIVINE ×64. В игре характеристики карточек из JSON пока не изменяются усилениями.

## Проверки

Запустить все модульные тесты:

```bash
mvn test
```

Тесты `CardJsonLoader` проверяют чтение JSON, наличие изображений, уникальность ID и отказ на некорректных данных. Интеграционные проверки с PostgreSQL пока не настроены.
